# Instructions for all Hero Academy development work

Before planning or editing **any** Hero Academy application, read [HERO_ACADEMY_DEVELOPMENT_STANDARD.md](https://github.com/mightora/hero-academy/blob/main/HERO_ACADEMY_DEVELOPMENT_STANDARD.md) completely and the project's own `BRAND.md` and `AGENTS.md` if present.

Treat ChoreQuest as the **single family identity and authorised learning-activity hub**. Every new game must be designed for optional, secure ChoreQuest linking with parent permission, scoped credentials, offline local play, cloud save conflict handling and aggregate activity reporting. Games remain usable without signing in. Never invent a second login provider or send parent session cookies to a game.

Follow the standard's accessibility, child privacy, brand, testing and release gates. Do not turn a disabled catalogue entry on until its exact canonical origin and client integration are deployed and verified. Preserve existing player data and working features. If a task cannot safely reach production, deliver reviewed changes and state the explicit deployment blocker.
